RULES PROVED HERE
1. SWITCH DISPATCH SHAPE (func_0012E250, 320 bytes, decisive).
   Retail "beq r,K1 -> far label; bne r,K2 -> end; <K2 body inline>" is a SWITCH,
   not an if/else chain.  GCC compares the case values in VALUE order but emits the
   case BODIES in SOURCE order.  An if/else chain always puts the FIRST tested body
   inline, so it can never produce this.  Write the cases in the order the bodies
   appear in retail, which for E250 meant `case 0xC:` before `case 0xB:`.
   A 2-case switch emits sequential compares and NO .rodata jump table, so the
   "jump-table switches are a blocker" rule does not apply to small switches.
2. `volatile` on a global pointer is what forces retail's SECOND load of that
   pointer; without it GCC 2.95 CSEs the two loads into one even across a branch
   and across a short store through the pointer (proved by recompiling the accepted
   src/game/func_0013A748.c with the volatile removed: one load, mismatch).
   Conversely `volatile` BLOCKS the delay-slot fill -- see blocker (B) below.
   func_0013B210 matched only after DROPPING volatile, because retail's second load
   sits in a branch delay slot.
3. `-fno-strict-aliasing` passed as an object flag reaches cc1 (verified: `-O0` as an
   object flag changes the output) but does NOT change this CSE, so type-based
   aliasing is not the mechanism.
4. Struct-field copy order decides the base-register anchor: in func_0012C8B0 the
   2-byte entry copy anchored at +5 (retail) vs +4 (mine) purely from writing
   `.id = ...` before `.count = ...`.  dist 3 -> MATCH.
5. Post- vs pre-decrement timers are distinguishable in retail:
   `lhu / addiu / sll / blez / sh(delay)` = test the ORIGINAL (post-decrement,
   `unsigned short remaining = f; f = remaining-1; if ((short)remaining > 0)`).
   `lhu / addiu / sh / sll / blez`        = test the DECREMENTED value; use an
   `int` temp (`int r = f_uh - 1; f_uh = r; if ((short)r > 0)`) -- a `short` or
   `unsigned short` temp inserts a stray `sra`/`andi 0xFFFF`.
